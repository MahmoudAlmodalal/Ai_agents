# مواصفات وحدة التعلّم: هندسة الباك إند بالذكاء الاصطناعي ومسار موازاة الوكلاء
## (AI-Assisted Backend Engineering & Parallel Agent Pipeline Spec)

## Problem Statement

بعد إتمام واجهة المستخدم (Frontend)، يواجه المتعلمون ومطورو البرمجيات بالذكاء الاصطناعي فجوة منهجية عند الانتقال لبناء الخادم الخلفي (Backend):
- اللجوء للمطالبات العشوائية (مثل "ابنِ لي الباك إند") يدفع وكلاء الذكاء الاصطناعي إلى الهلوسة، وابتكار مسميات حقول لا تطابق الفرونت إند، واختيار هياكل بيانات هشة.
- يجهل المتعلم كيف يوجه الذكاء الاصطناعي لاختيار قاعدة البيانات وتوليد مخططات ERD وعقود API بصيغ منضبطة قبل كتابة سطر كود واحد.
- ينتج الذكاء الاصطناعي بشكل افتراضي كود Django سطحي (Fat Views و Fat Models) تفتقر إلى عزل القراءة عن الكتابة (CQS) وتفشل في معالجة استعلامات N+1 وتضارب التزامن.
- غياب معرفة الطالب بكيفية تشغيل عدة وكلاء بالتوازي عبر مسارات عمل معزولة (Git Worktrees) وقوالب موجزات مقيدة (Briefs)، مما يوقعهم في فوضى تعارض الدمج وتخريب الملفات.

---

## Solution

تطوير وحدة تعليمية تطبيقية متكاملة في المنصة تمكّن المتعلم من **قيادة وكلاء الذكاء الاصطناعي كمهندس معماري ومراجع صارم (Architect & Reviewer)** لبناء الواجهة الخلفية خطوة بخطوة، متضمنة:
1. **كتالوج البرومبتات الهندسية الموجهة العامة:** برومبتات نموذجية عامة بمحددات ومتغيرات واضحة (`[PROJECT_NAME]`, `[DOMAIN_SUMMARY]`, `[CORE_ENTITIES]`) لتوليد خطة الفيزات، ومخطط ERD، وعقود API.md، وتجهيز Docker و Supabase وحماية الأسرار لأي مشروع يختاره الطالب.
2. **برومبتات المعمارية الصارمة:** توجيه الوكيل لبناء طبقات Django الثمانية (`Models → Policies → Permissions → Selectors → Services → Views → Serializers → URLs`) وفرض عزل CQS و Thin Views.
3. **منهجية موازاة الوكلاء (Matt Pocock Lifecycle):** تدريب المتعلم على قيادة دورة حياة الميزات (`grill-with-docs` -> `to-spec` -> `to-ticket` -> `Briefs` -> `Git Worktrees`) لتنفيذ تذاكر الباك إند بالتوازي بنسبة نجاح 100%.
4. **دراسة حالة اختيارية قابلة للفحص:** إتاحة متجر حلويات كاندي لوز (أو دراسة حالة BorrowHub) كأمثلة استرشادية حية توضح للمتعلم كيف تبدو المخرجات النهائية عند تعبئة المتغيرات.

## User Stories

### مسار التخطيط والتصميم بالذكاء الاصطناعي (AI Modeling & Contracts)
1. كـ طالب هندسة بالذكاء الاصطناعي (Learner)، أريد برومبتاً موجهاً لاستكشاف متطلبات الباك إند من PRD وعقود الفرونت، لأحصل على خطة تنفيذ مفصلة مقسمة إلى فيز (Phases) واضحة.
2. كـ طالب، أريد برومبتاً يطلب من الوكيل مقارنة SQL مقابل NoSQL بناءً على طبيعة مشروعي، ليبرر لي هندسياً سبب اختيار PostgreSQL.
3. كـ طالب، أريد برومبتاً لتوليد مخطط علاقات الكيانات (`ERD.md`) بصيغة Mermaid مع معرفات بادئة (`cat_*`, `ord_*`) وآلة حالات (State Machine)، لأثبت نموذج البيانات قبل أي كود.
4. كـ طالب، أريد برومبتاً لصياغة عقود الـ API (`API.md`) بنمط CamelCase وغلاف استجابة موحد (`{ success, data, error, meta }`)، ليطابق الخادم الواجهة الأمامية بدون احتكاك.

### مسار البنية التحتية والأمان بـ AI (Infra & Security)
5. كـ طالب، أريد برومبتاً يوجه الوكيل لإعداد ملف `docker-compose.yml` و `.env.example`، لتوحيد بيئة العمل محلياً مع توفير متطلبات ربط Supabase.
6. كـ طالب، أريد برومبتاً يفرض قواعد `.gitignore` صارمة تمنع الوكيل أو المطور من تسريب مفاتيح وقواعد بيانات التطوير.

### مسار توجيه الوكيل لمعمارية Django (Strict Django Layering)
7. كـ طالب، أريد برومبتاً يمنع الوكيل من إنشاء Fat Views أو Fat Models، ويلزمه بنمط الطبقات الثمانية وعزل المحددات (`selectors.py`) عن الخدمات الذرية (`services.py`).
8. كـ طالب، أريد برومبتاً يوجه الوكيل لمنع استعلامات N+1 عبر `select_related` و `prefetch_related`، لضمان كفاءة أداء الخادم.
9. كـ طالب، أريد برومبتاً يوجه الوكيل لتطبيق أقفال التزامن `select_for_update` ودعم مفتاح منع التكرار `Idempotency-Key` في العمليات الحساسة.

### مسار إدارة الوكلاء المتوازيين (Parallel Agents Orchestration)
10. كـ طالب، أريد نموذج Brief معياري بصيغة XML (7 أقسام)، لأقيد الوكيل بنطاق ملفات محدد (`allowed_scope`) وأمنعه من تخريب باقي أجزاء النظام.
11. كـ طالب، أريد خطوات عملية لعزل مساحات عمل الوكلاء عبر `git worktree`، لأتمكن من تشغيل 3 وكلاء بالتوازي في نفس الدقيقة دون تعارضات دمج.
12. كـ طالب، أريد برومبت مراجعة كود وتحقق (Reviewer Prompt)، لأفحص مخرجات الوكيل قبل قبول دمجه في الفرع الرئيسي.
