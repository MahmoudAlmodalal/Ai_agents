# مراجعة #26 و#28 — المراجع أثناء مسار المشروع

تاريخ الفحص: 2026-10-19. المرجع: أقسام 11 و14 و15 من `Weapon_of_the_Era_Website_Content_AR.md`، ومواصفة مسار المشروع. هذه مراجعة تنفيذية/تعليمية وليست موافقة مالك المحتوى #33.

## #26 — BorrowHub

**Passed — فحص المحتوى والمخرج:** استبدلت القواعد العشر غير المسندة بالقواعد التسع المنقولة من المصدر: اعتماد يدوي؛ وحدة لكل طلب؛ طلبان نشطان؛ عشرة أيام؛ سبب مطلوب؛ مهلة استلام مرتبطة بتاريخ بداية الطلب وفق التعريف الموثق؛ تأكيد المسؤول للتسليم والإرجاع؛ التلف لا يعود للمتاح؛ متابعة التأخر يدويًا دون حظر تلقائي. لا غرامة مفترضة أو توقيع إلزامي.

المثال المحلول المفحوص: طالبة معتمدة بلا طلبات نشطة تطلب كاميرا واحدة خمسة أيام لغرض موضح؛ المسؤول يراجع الطلب ويسلم الكاميرا فعليًا ثم يؤكد الإرجاع والفحص. عند التلف يسجله دون زيادة المتاح. هذا يتبع قواعد العدد والمدة والدور؛ لا يدعي مقابلة أو تشغيل Backend. المخرج قابل للمراجعة: طلب وإجراءات منفصلة بمسؤولها، ثم جدول تعارضات عند استخدام برومبت المراجعة مع PRD فعلي.

الأدوار Student وAdministrator/Staff منفصلة. الجداول الخمسة مطابقة لأسماء المصدر، وعلاقات الطالب/المعدة/الفئة/الطلب/سجل الإجراء موضحة. تحدي تزامن الكميات يطلب مراجعة ذرية التحديثات دون الادعاء أن الرسم يحققها.

**حدود التوفر:** فُحصت مسارات ملفات الحالة الاثني عشر محليًا؛ لا توجد ملفات BorrowHub المعتمدة بهذه المسارات ولا مجلد public يوفرها. تعرض الصفحة كل ملف «غير متاح» ولا تولد تنزيلًا. روابط مراحل المشروع تصل إلى مواضيع منشورة فعلية. لا يمكن إثبات مطابقة المثال مع PRD حالة غير مرفوع؛ التحذير يطلب توثيق التعارض وسؤال المالك.

## #28 — القاموس والأسئلة

**Passed — فحص المحتوى والمخرج:** نُقلت مصطلحات المصدر الـ35 كاملة مع تعريفاتها العربية، بما فيها SRS وBusiness Rule وGit/Commit/Branch وActivity/Sequence/State/Class وPK/FK وCardinality وMock Data وQA. البحث يشمل المصطلح والتعريف، ويزيل التشكيل والتطويل ويوحد أشكال الألف والياء المقصورة وحالة الحروف الإنجليزية. مثال الفحص: `أَجْنَبِيَّة` يعيد PK / FK فقط؛ `sequence` يعيد Sequence Diagram؛ النص غير الموجود يظهر حالة خالية وإفراغ البحث يعيد 35.

راجعنا أجوبة FAQ مقابل الفرق المفاهيمي: PRD للمنتج، SRS للسلوك والاختبار، DESIGN.md للنظام البصري؛ Domain Model للمفاهيم وERD للتخزين؛ Mermaid/PlantUML/DBML بحسب نوع المخطط. الجواب عن Stitch يميز مرحلة Frontend ببيانات تمثيلية عن المسار Full-Stack الذي يستكمل API وBackend والصلاحيات والاختبار والنشر. الروابط أصبحت روابط موضوع منشور بدل ذكر URL كنص، وحذفت ترشيحات موديلات وأسعار مجانية غير متحقق منها.
