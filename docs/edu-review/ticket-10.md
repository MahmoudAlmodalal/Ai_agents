## 1. ملخص المراجعة ونطاق العمل

تحقق هذه التذكرة الربط الفعلي بين مرحلة التصميم البصري (المواضيع 21 و22 و23) ومرحلة التجهيز لكود الفرونت إند في Next.js (الموضوع 30 فصاعداً). ينقل الطالب في هذه المحطة التصميم المعتمد ونموذجه التفاعلي إلى بيئة تنفيذ الفرونت عبر موضوعين مستقلين ومحكمين:

1. **الموضوع 28 (ربط Stitch MCP واسترجاع مراجع التصميم البصري - `stitch-mcp-integration`):**
   - **التموضع الهندسي السليم:** يأتي ربط Stitch MCP بعد اكتمال تصميم واعتماد الشاشات في Google Stitch (المواضيع 21-23) وبعد تهيئة وكيل البرمجة وأسس بروتوكول MCP (المواضيع 24 و27). خادم Stitch MCP مخصص لقراءة مراجع حقيقية موجودة بالفعل؛ فلا يُشترط ربطه في المراحل المبكرة ولا معنى لاستدعائه قبل اكتمال التصميم.
   - **حوكمة الأسرار ومنع تسريب المفاتيح:** توضيح آليات إدارة أسرار الاتصال ومفاتيح API بأمان محلياً (عبر إعدادات المضيف أو `.env.local` المحمية بـ `.gitignore`)، مع فرض حظر أمني بات على كتابة أي مفاتيح حقيقية في المستودع أو ملفات PRD أو README أو الأمثلة البرمجية، والاكتفاء بعلامات الحجز العامة (مثل `<YOUR_STITCH_API_KEY>`).
   - **برومبت التحقق من الاتصال (PROMPT 22):** استدعاء البرومبت المعتمد بصلاحية قراءة فقط (Read-only) لحصر معرّفات الشاشات والتأكد من عدم تعديل أو حذف أي عنصر ومنع تسريب المفاتيح.
   - **المسار البديل اليدوي الكامل (Manual Fallback Path):** توفير مسار بديل موثق خطوة بخطوة في حال تعذر تشغيل خادم MCP أو عدم توفر المفتاح، يقوم فيه الطالب بتصدير لقطات الشاشات وأكواد الألوان والتوكنز يدوياً من واجهة Stitch وحفظها في `docs/assets/screens/`، مما يضمن استمرارية التعلم بنسبة 100% دون أي توقف.
   - **المخرج الأساسي:** إنشاء وثيقة `docs/STITCH_SCREEN_REFERENCES.md` لحصر الشاشات ومعرفاتها وروابطها وحالتها الواقعية.

2. **الموضوع 29 (وثيقة التصميم DESIGN.md واستخراج القيم المعتمدة - `design-md-spec`):**
   - **المبدأ الهندسي الصارم:** تعكس وثيقة التصميم القيم البصرية المعتمدة فعلياً من نموذج الطالب وشاشات Stitch، ولا تخترع هوية بصرية جديدة من العدم أو تستبدل متطلبات PRD المعتمدة.
   - **الهيكل القياسي لـ DESIGN.md (Google Design Spec):** هيكلة الوثيقة إلى ركيزتين: قسم رموز التصميم المهيكلة (Design Tokens في YAML Frontmatter) لدعم إعدادات Tailwind CSS برمجياً، وقسم الشرح الهندسي والأسس البصرية (Markdown Design Rationale) لتحديد الهرم البصري والحالات التفاعلية ودعم اللغة العربية (RTL First).
   - **برومبت استخراج DESIGN.md (PROMPT 23):** استخدام البرومبت المعتمد لتوجيه الوكيل بصفته مهندس نظام تصميم منضبط يستخرج القيم المؤكدة فقط ويمنع اختراع القيم.
   - **إتاحة الوصول والحالات التفاعلية:** فحص نسب التباين وفق WCAG AA (4.5:1 للنصوص)، وتوثيق الحالات الست الإلزامية لكل مكون (Default, Loading, Empty, Error, Disabled, Permission Denied).
   - **المراجعة التعليمية للمطابقة البصرية:** إجراء فحص يدوي دقيق يطابق كل قيمة Hex ومقياس خط في الوثيقة مع الشاشات المعتمدة في النموذج التفاعلي لمنع التخمين والبرمجة العشوائية (Vibe Coding).
