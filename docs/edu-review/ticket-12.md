## 1. ملخص المراجعة ونطاق العمل

تحقق هذه التذكرة المحطة التنفيذية المركزية لتحويل التصميمات والتحليلات المعتمدة إلى كود برمجي منظم للواجهة الأمامية؛ حيث يتبع الطالب مواضيع **Frontend Planning**، و**UI/UX Pro Max**، و**Spec Kit**، و**تنفيذ Frontend التدريجي** لبناء واجهة تطبيقه خطوة بخطوة عبر مهام ذرية صغيرة قابلة للتحقق الفوري (Small Verifiable Tasks).

تغطي التذكرة أربع محطات تعليمية متتابعة ومستقلة:
1. **الموضوع 34 (تخطيط واجهة المستخدم وهندسة الفرونت إند - Frontend Planning):** تفكيك متطلبات PRD وجرد الشاشات ونظام التصميم إلى شجرة مسارات Next.js App Router معمارية، وهرمية مكونات تفصل المكونات القاعدية (UI Primitives) عن مكونات الميزات، وتحديد عقود البيانات المكتوبة (TypeScript Data Contracts) المشتقة من ERD، وجدولة المهام الذرية الصغيرة (Small Verifiable Tasks) المحددة بالمدخلات والاعتماديات ومعايير القبول وأوامر الفحص الفوري.
2. **الموضوع 35 (مراجعة معايير التجربة والواجهة بـ UI/UX Pro Max):** توظيف الأداة في موضع استخدامها الطبيعي قبل بدء الكود وبعد بناء المكونات، مع مراجعة واعتماد أوامرها مقابل المستودع الرسمي (`github.com/nextlevelbuilder/ui-ux-pro-max-skill`)، وتطبيق أبعاد التدقيق الخمسة: الدقة البصرية وتوكنز التصميم، الحالات التفاعلية، إمكانية الوصول (WCAG AA &ge; 4.5:1)، أهداف اللمس للهواتف (&ge; 44×44px)، ومرونة التجاوب مع انعدام التمرير الأفقي.
3. **الموضوع 36 (تنظيم المواصفات وتطوير الميزات بـ Spec Kit):** اعتماد منهجية التطوير القائم على المواصفات الرسمية من GitHub (`specify-cli`)، ومراجعة متطلباتها (Python / uv) وأوامرها مقابل المستودع الرسمي (`github.com/github/spec-kit`)، مع تحذير الحفظ المسبق بـ Git Commit قبل التهيئة، وتأسيس دستور المشروع البرمجي (`docs/rules/frontend.md`)، وتطبيق دورة حياة تطوير الميزة بالأوامر المنفصلة (Specify &rarr; Clarify &rarr; Plan &rarr; Tasks &rarr; Analyze).
4. **الموضوع 37 (التنفيذ التدريجي للفرونت إند وحالات الواجهة):** تطبيق حلقة التنفيذ الهندسية الثلاثية الصارمة (فحص التغيير بأوامر الطرفية tsc وbuild والتجاوب &larr; الرجوع للمتطلبات والتصميم في PRD وDESIGN.md &larr; حفظ العمل بـ Git commit وصفي)، مع توضيح حدود الفرونت إند وعزل البيانات التمثيلية (Mock Data) المكتوبة الأنواع دون أي ادعاء كاذب بوجود تكامل أو خادم حقيقي قبل مرحلة الربط، وإلزامية تغطية حالات الواجهة الأربع (Loading, Success, Empty, Error).
