# مراجعة تعليمية: نشر Backend وقاعدة البيانات (الموضوع 54)

**التذكرة:** مسار المشروع 18 — GitHub #22
**الموضوع:** 54 · `backend-database-deployment`
**تاريخ مراجعة المحتوى والمراجع:** 2026-10-19
**المخرج المتوقع:** API عبر HTTPS يتصل بخادم PostgreSQL، وإعداد أسرار وCORS آمن، وخطة إصدار واستعادة، وسجل smoke tests شامل من الواجهة حتى قاعدة البيانات.

## دليل المراجعة التعليمية

- راجعت ترتيب المتطلبات: إطار Django أو FastAPI المختار، PostgreSQL وعقود API، ومضيف واجهة واحد من الموضوع 52 أو 53.
- تحققت من مطابقة مثال FastAPI لأمر Render الرسمي في [دليل Deploy FastAPI](https://render.com/docs/deploy-fastapi): أمر التثبيت `pip install -r requirements.txt`، وأمر Uvicorn على `0.0.0.0` و`$PORT`. يوضح الموضوع أن `main:app` مثال يتطلب استبداله بمسار التطبيق الحقيقي. رابط Django منفصل للمسار البديل.
- راجعت توجيه Render باستخدام عنوان PostgreSQL الداخلي إذا كانت الخدمة والقاعدة في الحساب والمنطقة نفسيهما، ومتطلبات عنوان الاتصال الخارجي وTLS في [وثائق إنشاء واتصال PostgreSQL](https://render.com/docs/postgresql-creating-connecting).
- راجعت إعداد الأسرار في [وثائق متغيرات البيئة](https://render.com/docs/configure-environment-variables)، وفحص الصحة 2xx/3xx خلال خمس ثوانٍ في [وثائق Health Checks](https://render.com/docs/health-checks)، وسجلات التشغيل في [وثائق Logging](https://render.com/docs/logging)، وTLS عبر [وثائق Web Services](https://render.com/docs/web-services).
- يتضمن المحتوى ضبط CORS على أصل الواجهة المحدد، وعدم كشف `DATABASE_URL` أو `SECRET_KEY`، وفحص التهجيرات والنسخ الاحتياطية قبل التغيير. كما يميز بين تراجع نسخة التطبيق واستعادة قاعدة البيانات.
- خطة smoke test تغطي HTTPS، ونقطة الصحة، وإنشاء/قراءة/تعديل بيانات اختبار من الواجهة إلى API ثم PostgreSQL، ورفض المصادقة أو الأصل غير المسموح، وفحص السجلات وتسجيل Passed/Failed/Not Run.
