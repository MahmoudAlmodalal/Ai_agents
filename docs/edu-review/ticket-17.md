## الموضوع 50: Docker

- **المخرج المتوقع:** `docs/DOCKER_DECISION.md`؛ و`backend/Dockerfile` و`.dockerignore` عند اختيار صورة للخادم؛ و`compose.yaml` اختياري للتطوير المحلي متعدد الخدمات. يمكن أن يكون Dockerfile في مجلد الواجهة إذا كان مشروع Next.js مختارًا لصورة تشغيل.
- **المتطلبات السابقة:** اختيار إطار الخادم وأمر إنتاجه، إعداد Next.js وملف الاعتماديات، وتحديد هدف النشر وهل يقبل OCI image أو يبني المصدر من Git.
- **التتبع التعليمي الساكن:**
  - مثال Python يستخدم `backend/` كسياق بناء، ويخصص Uvicorn لـ FastAPI وGunicorn لـ Django؛ لا يطلب بناء الخادم مرتين.
  - مثال Next.js متعدد المراحل يشترط إخراج `standalone`، وملف npm lock ونسخة Node توافق المشروع. لا يفترض وجود `public/`.
  - يفرق بين بناء الصورة ونشر الخدمة، ويشرح `.dockerignore` وملف البيئة المحلي والأسرار ومستخدم تشغيل غير root.
  - يربط منفذ التطوير على `127.0.0.1`، ويحذر من `--privileged` ومجموعة Docker واسعة الصلاحية، ويوضح متى يمكن لمنصة مُدارة أن تحل محل Docker.
  - لا يفرض Compose أو قاعدة بيانات داخل حاوية أو Linux ذاتي الإدارة.
- **مراجعة السلامة وإعادة الإنتاج:** الأسرار لا تدخل الصورة أو build context. يذكر الدرس أن متغيرات الحاوية قد تظهر لصاحب صلاحية Docker أو في بيانات الفحص، ويوجه أسرار الإنتاج لمدير المنصة وأسرار البناء إلى BuildKit secret mount. وسما `python:3.12-slim` و`node:24-slim` أمثلة تحتاج مواءمة وتثبيتًا متعمدًا في النشر.
- **الحالة:** فحص المحتوى والاتساق: **Passed**. إنشاء مخرج خاص بمتعلم وتجربة البناء أو التشغيل: **Not Run**.
- **الفجوة:** لا توجد صورة مبنية أو مشروع فعلي للتحقق من نسخ الملف أو الاعتماديات أو الاتصال بقاعدة البيانات؛ يلزم فحص ذلك في بيئة اختبار يختارها المتعلم قبل النشر.

## الموضوع 51: Linux

- **المخرج المتوقع:** `docs/LINUX_RUNTIME_NOTES.md` إذا كان المتعلم يدير Linux، أو توثيق سبب تجاوز الإدارة اليدوية ومرجع المنصة المُدارة.
- **المتطلبات السابقة:** اختيار إطار خادم واحد وأمر تشغيل إنتاجي، وتحديد مسؤولية نظام التشغيل لدى منصة الاستضافة، وحصر ملفات الإعداد ومجلدات الكتابة.
- **التتبع التعليمي الساكن:**
  - يبدأ بأوامر قراءة فقط (`id`, `ls`, `stat`, `namei`) ويشرح علاقة الهوية والمالك والمجموعة وإذن العبور للمجلد.
  - يشرح `0640` و`0750` كأمثلة محددة لا وصفات شاملة، ويوصي بحساب خدمة غير root ومجلدات كتابة محصورة.
  - يقيّد `sudo chown` و`chmod` بالتحقق من الحساب والمسار والإذن وخطة الرجوع، ويحذر من `chmod -R 777`.
  - يشرح أن أذونات الملف تحد القراءة من القرص لكنها لا تخفي السر عن العملية أو مدير النظام ولا تحمي النسخ الاحتياطية والسجلات تلقائيًا.
  - يفرق بين تشغيل حاوية Linux وإدارة مضيفها، ويسمح بتجاوز أوامر Linux عند استخدام استضافة مُدارة.
- **الحالة:** فحص المحتوى: **Passed**. تجربة على مستخدم أو خادم فعلي وفحص مخرجات متعلم: **Not Run**.
- **الفجوة:** أمثلة المسارات والمجموعة `project-api` افتراضية؛ لا يمكن تنفيذها دون مطابقتها لإعداد الخدمة الفعلي. لم تتغير ملكية أو صلاحية على أي مضيف.

## تتبع مكتبي للمخرج التعليمي

هذا سيناريو افتراضي لمراجعة اتساق الخطوات وليس مخرج مشروع مستخدم:

1. يختار المتعلم Next.js على منصة تبني من Git، فيوثق تجاوز صورة الواجهة. إذا طلب هدف Backend صورة OCI، يكتب Dockerfile للخادم المختار وملف تجاهل بعد مطابقة build context وملف القفل.
2. يستثني `.env.local` من Git وDocker context، ويحتفظ بقيم محلية غير إنتاجية؛ ثم يسجل مدير الأسرار الذي ستستخدمه المنصة.
3. إذا كانت خدمة Backend مُدارة، يسجل أن المزود يدير Linux ويتجاوز `chmod` و`chown`. إذا انتقل لاحقًا إلى VM يديرها، يبدأ بفحص الهوية والمسارات ثم يراجع الملكية مع مسؤول النظام.

هذا التتبع لم ينشئ ملفات `docs/DOCKER_DECISION.md` أو `docs/LINUX_RUNTIME_NOTES.md` ولم يختبر صورة أو شبكة. اكتمال مخرج المتعلم يحتاج مشروعه ومنصة نشره الفعليين.

## ما لم يُنفذ

- لم يثبت Docker أو Linux أو أي اعتماد على حساب المستخدم أو أجهزته.
- لم يُشغّل `docker build` أو `docker run` أو Compose، ولم تُنشأ صورة أو حاوية أو موارد سحابية.
- لم تُنشأ ملفات أسرار، ولم يُستخدم مفتاح API أو اتصال قاعدة بيانات، ولم تُرفع صورة إلى سجل.
- لم تُشغّل أوامر `sudo` أو `chmod` أو `chown` على مضيف، ولم تتغير ملفات أو صلاحيات.
- نجحت اختبارات المتصفح والنسخ والتنقل والمراجع؛ لم تُفحص هذه المادة بصريًا يدويًا ولم تُشغّل أوامر Docker أو Linux.
- لم يُنشأ مخرج متعلم؛ أسماء ملفات المخرجات في الدرس أهداف تطبيقية مستقبلية.

هذه المراجعة لا تثبت الأداء أو الأمان الكامل أو الجاهزية للنشر. يلزم فحص ملفات المتعلم وتشغيلها في بيئة اختبار ملائمة ومراجعة مسؤول الاستضافة عند إدارة Linux.
