## الموضوع 05: Git — حفظ وثائق المشروع وتتبع النسخ محلياً

- **معرّف الموضوع:** `topic-05-git`
- **المعرف الدلالي (Canonical Slug):** `git-project-docs`
- **الموقع في المسار (Sequence Position):** 5
- **المرحلة:** المرحلة التأسيسية (`foundations`) — إدارة النسخ وتوثيق المشروع
- **المخرجات التعليمية المستهدفة:**
  1. مستودع Git محلي مهيأ بنجاح (`.git`).
  2. ملف `.gitignore` محكم لحماية الأسرار وملفات البيئة والمفاتيح المؤقتة.
  3. أول نقطة حفظ (`First Commit`) موثقة تحفظ مجلد `docs/` وملف `README.md`.
- **حالة المراجعة:** Passed

### 1. Expected output (المخرج المتوقع)
1. **مستودع محلي مهيأ:** تنفيذ `git init` في المجلد الجذري لمشروع الطالب مع ضبط `user.name` و `user.email`.
2. **حماية الأسرار مبكراً:** وجود ملف `.gitignore` يستبعد `.env`, `.env.local`, `*.key`, `*.pem`, `*.token`, `node_modules/`, وملفات النظام التشغيلي قبل تسجيل أي Commit، مع توفير نموذج إرشادي آمن `.env.example`.
3. **حفظ وثائق المتطلبات:** إضافة مجلد `docs/` الحاوي على وثائق الفكرة والمتطلبات السابقة (`PROJECT_CONTEXT.md` و `PRD.md` و `SRS.md`) وسجل Commit أولي بمعيار دلالي (`docs: ...`).
4. **فروع العمل والتراجع الآمن:** إنشاء فرع مستقل للتوثيق (`git switch -c docs/srs-spec`)، فحص الفروقات بـ `git diff` و `git diff --staged`، والتنقل الآمن دون أوامر تدميرية (`git reset --hard`).

### 2. Inspected evidence (دليل فحص المخرج وتجربته)
- **توحيد المرجعية والمحتوى:**
  - مطابقة بيانات بطاقة الفهرس في الصفحة الرئيسية (`/`) والنافذة التفصيلية (`TopicDetailModal`) وصفحة القراءة المستقلة (`/learn/git-project-docs`).
  - تعكس البطاقات بيانات Git الحقيقية (الوسوم: `Git`, `Version Control`, `.gitignore`, `Commit`, `Branch`, `docs`, `Secrets Protection`) دون أي ذكر متبقٍ لمخططات UML أو انتظار محاضرة.
- **مراجعة الأوامر والتحقق الرسمي:**
  - تمت مراجعة جميع الأوامر مقابل المرجع الرسمي لـ Git على [git-scm.com/doc](https://git-scm.com/doc) للنسخة 2.23+:
    - `git --version`, `git config --global user.name`, `git config --global user.email`: محققة رسمياً.
    - `git init`, `git status`, `git add`, `git commit`: محققة رسمياً.
    - `git switch -c`, `git diff`, `git diff --staged`, `git log --oneline`: محققة رسمياً.
- **فحص السلوك والاختبارات الآلية (Playwright E2E):**
  - تم التحقق آلياً عبر `e2e/path/git-github.spec.ts` من ظهور بيانات البطاقة الحقيقية، وعرض تفاصيل الموضوع في نافذة القراءة، وظهور حالة النشر `مسار موحد مكتمل ✓`، والمخرجات وقائمة التحقق، وصحة روابط التنقل السابق (`project-idea-mvp`) والتالي (`github-docs-collaboration`).

### 3. Gaps (الفجوات والإجراء التصحيحي)
- **الفجوة المرصودة:** كان المفهوم التقليدي يخلط بين حفظ الوثائق وبين إعداد أدوات كود الفرونت إند ومكتبات التطوير.

## الموضوع 06: GitHub — المستودع البعيد والمراجعة والتعاون وحماية الأسرار

- **معرّف الموضوع:** `topic-06-github`
- **المعرف الدلالي (Canonical Slug):** `github-docs-collaboration`
- **الموقع في المسار (Sequence Position):** 6
- **المرحلة:** المرحلة التأسيسية (`foundations`) — المستودع البعيد والمراجعة
- **المخرجات التعليمية المستهدفة:**
  1. مستودع GitHub بعيد مرتبط بالمشروع المحلي (`origin`).
  2. ملف `README.md` احترافي يوضح فكرة المشروع وروابط وثائقه المعتمدة في `docs/`.
  3. دورة مراجعة وثائق عبر رفع فرع عمل وفتح طلب دمج (`Pull Request`) وفحص الأسرار.
- **حالة المراجعة:** Passed

### 1. Expected output (المخرج المتوقع)
1. **ربط المستودع البعيد:** إنشاء مستودع جديد على GitHub (دون توليد ملفات افتراضية متعارضة)، استخدام مصادقة آمنة (SSH أو Fine-grained PAT) وتجنب كلمات المرور الصريحة، وتثبيت مرجع الفرع `main` عبر `git push -u origin main`.
2. **ملف README احترافي للوثائق:** قالب منظم يعرّف باسم المشروع، المشكلة الواقعية، نطاق MVP، وروابط مباشرة لملفات `docs/PROJECT_CONTEXT.md` و `docs/PRD.md` و `docs/SRS.md`، مع توضيح سياسة الأسرار وحالة المشروع.
3. **حماية الأسرار ومنع التسريب:** توضيح آلية عمل GitHub Secret Scanning و Push Protection، وإجراء الفحص الاستباقي قبل كل عملية Push (`git log -p -1`).
4. **دورة مراجعة الوثائق (Documentation PR Review):** رفع فرع التوثيق `git push -u origin docs/srs-spec`، فتح Pull Request على GitHub، فحص التغييرات نقدياً، ومزامنة الفرع الرئيسي محلياً بعد الدمج `git pull origin main`.

### 2. Inspected evidence (دليل فحص المخرج وتجربته)
- **توحيد المرجعية والبيانات:**
  - تم ربط الموضوع في الفهرس والنافذة وصفحة القراءة `/learn/github-docs-collaboration`.
  - بطاقة الفهرس تعرض وسوم وبيانات GitHub الصريحة (`GitHub`, `Remote Repository`, `README.md`, `Pull Request`, `Code Review`, `Secrets Protection`, `Collaboration`).
  - لا توجد روابط تنزيل وهمية أو طلب نشر عام غير مصرح به.
- **مراجعة الأوامر والتحقق الرسمي:**
  - تمت مراجعة أوامر وإرشادات المنصة مقابل التوثيق الرسمي على [docs.github.com](https://docs.github.com):
    - `git branch -M main`: محقق رسمياً.
    - `git remote add origin`, `git remote -v`: محقق رسمياً.
    - `git push -u origin main`, `git push -u origin docs/...`: محقق رسمياً.
    - `git pull origin main`, `git branch -d`: محقق رسمياً.
    - إرشادات Secret Scanning والمصادقة الآمنة مستندة إلى docs.github.com/code-security.

  - تم اختبار نسخ برومبت التوثيق المعتمد `PROMPT 04` من مكتبة البرومبتات والتأكد من تطابق النص المنسوخ وسلامته.
